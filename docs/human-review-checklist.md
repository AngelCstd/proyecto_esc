# Noktos Auth V1 human-review checklist

This handoff inventories the repository as implemented. A checked item means that the cited code or documentation exists; it does not imply production deployment or end-to-end coverage where the item is explicitly marked partial.

## Implemented controls

- [ ] **Reviewer: confirm the Auth-only boundary.** The intended path is external consumer -> Noktos Auth -> `CoreClient` -> `AppClient` -> Noktos Core. `CoreModule` constructs the only configured outbound client from `CORE_BASE_URL`, injects a replaceable auth strategy, and exports `CoreClient` (`src/core/core.module.ts`, `src/core/core-client.ts`, `src/app-client/app-client.ts`). The public contract records the same boundary (`docs/integration-contracts.md`). A repository-wide reviewer search should confirm that no other Core transport has been added.
- [ ] **Reviewer: verify startup configuration validation.** Required database, Supabase, Core URL, and Core timeout values are validated before application startup; URLs are constrained to HTTP(S), and the timeout must be a positive integer (`src/config/environment.validation.ts`, `src/app.module.ts`). Confirm production values are supplied outside the repository.
- [ ] **Reviewer: verify Supabase human identity verification.** Bearer extraction is implemented by `HumanAuthGuard`; the verifier calls Supabase `auth.getUser(accessToken)` with client-side session persistence, refresh, and URL-session detection disabled (`src/identity/human-auth.guard.ts`, `src/identity/supabase-human-identity-verifier.service.ts`, `src/identity/supabase-client.provider.ts`). Failures are collapsed to a safe 401 response. The supplied access token is not forwarded to Core.
- [ ] **Reviewer: verify `public.user_info` mapping.** The trusted Supabase user ID is queried as `public.user_info.id_user`, selecting only identity context (`src/identity/prisma-user-info.repository.ts`, `prisma/schema.prisma`). Both `id_agente` and `id_viajero` are preserved when present.
- [ ] **Reviewer: verify Principal classification.** The normalized contract supports `agent_user`, `traveler_user`, `api_key`, and `service` (`src/identity/principal.ts`). Human classification uses only literal role values: `administrador` and `reservante` become `agent_user`; `viajero` becomes `traveler_user`; missing or unknown roles are rejected. Both agent and traveler IDs survive classification, and human scopes are deliberately empty because no role-to-scope matrix has been approved (`src/identity/human-principal-resolver.service.ts`).
- [ ] **Reviewer: verify centralized Core transport behavior.** `AppClient` owns base-URL resolution, JSON handling, timeout cancellation, transport-error normalization, and `x-request-id` forwarding; it rejects absolute, cross-origin, or base-path-escaping request paths (`src/app-client/app-client.ts`, `src/app-client/app-client.errors.ts`, `src/app-client/app-client.contracts.ts`). `CoreClient` delegates to this client (`src/core/core-client.ts`).
- [ ] **Reviewer: verify V1 outbound authentication is intentionally Noop.** `CORE_REQUEST_AUTH_STRATEGY` is injectable and currently bound to `NoopCoreRequestAuthStrategy`, which returns no auth headers (`src/core/core-request-auth-strategy.ts`, `src/core/noop-core-request-auth-strategy.ts`, `src/core/core.module.ts`). No signed internal assertion is implemented.
- [ ] **Reviewer: verify Core error sanitization.** Only caller-declared code/status pairs for 400, 403, 404, 409, 422, and 429 can be preserved; the public message comes from the trusted declaration rather than the upstream body. Core 500, timeout, network failure, malformed/undeclared responses, and internal Core 401 are mapped to sanitized 5xx responses (`src/core/core-failure.mapper.ts`, `src/core/core-public-error.ts`, `src/common/public-error-envelope.ts`).
- [ ] **Reviewer: verify API-key cryptography and stored representation.** Key generation uses 32 random bytes and the public `nok_test_` / `nok_live_` prefixes, returning the raw key only from the creation result while producing a SHA-256 hash and short display prefix for persistence (`src/api-credentials/api-key-generation.service.ts`, `src/api-credentials/api-credential-lifecycle.service.ts`, `src/api-credentials/prisma-api-credential.repository.ts`). Prisma stores the hash, not a raw-key field (`prisma/schema.prisma`).
- [ ] **Reviewer: verify API-key authentication and lifecycle primitives.** Authentication validates exact key form and environment, hashes the presented key, rejects absent, revoked, expired, or concurrently unusable records, updates `lastUsedAt`, and derives exactly one `agentId`, `credentialId`, and scopes from storage (`src/api-credentials/api-key-authentication.service.ts`, `src/api-credentials/prisma-api-credential.repository.ts`). Create, agent-scoped list, and idempotent active-to-revoked service/repository operations exist (`src/api-credentials/api-credential-lifecycle.service.ts`, `src/api-credentials/prisma-api-credential.repository.ts`).
- [ ] **Reviewer: verify general scope-checking primitives.** `@RequireScopes` metadata and `ScopeAuthorizationGuard` require an authenticated Principal and all declared scopes, returning safe 401/403 errors (`src/authorization/required-scopes.decorator.ts`, `src/authorization/scope-authorization.guard.ts`, `src/authorization/scope-authorization.ts`). Resource-specific business authorization remains Core's responsibility.
- [ ] **Reviewer: verify credential-safe request logging.** The globally applied middleware logs only method, decoded/sanitized pathname, status, and duration. It does not log headers, authorization values, query strings, or bodies, and redacts API-key/JWT-like values found in a path (`src/security/http-request-logging.middleware.ts`, `src/security/security.module.ts`, `src/app.module.ts`).
- [ ] **Reviewer: verify security-audit persistence primitives.** The owned `noktos_auth.security_audit_events` model and a Prisma append-only repository/recording service exist (`prisma/schema.prisma`, `src/security-audit/prisma-security-audit.repository.ts`, `src/security-audit/security-audit-recording.service.ts`). The stored contract omits raw credentials and authorization headers (`src/security-audit/security-audit.contracts.ts`).
- [ ] **Reviewer: verify Prisma ownership protection.** Prisma is configured for `public` and `noktos_auth`; `public.user_info` is mapped for access and declared external to migrations, while API credentials, scopes, and security audit events are mapped to `noktos_auth` (`prisma/schema.prisma`, `prisma.config.ts`). No real database migration is applied by this handoff.
- [ ] **Reviewer: verify documented integration contracts.** The Auth/Core boundary, Bearer credential dispatch, Principal shape, error policy, environment inputs, and current absent surface are documented in `docs/integration-contracts.md`.

## Partial controls requiring integration work

- [ ] **Request IDs are partial.** `AppClient` forwards a caller-supplied request ID to Core and the Core failure mapper includes it in public errors (`src/app-client/app-client.ts`, `src/core/core-failure.mapper.ts`, `src/common/request-context.ts`). There is no ingress middleware/interceptor that generates or captures request IDs, and there are no response routes demonstrating propagation end to end.
- [ ] **Human and partner ingress are primitives, not a complete public ingress surface.** Human and API-key guards parse `Authorization: Bearer ...`; API-key prefixes are exclusively accepted by the API-key guard and explicitly rejected by human authentication, preventing fallback between credential routes (`src/identity/human-auth.guard.ts`, `src/identity/human-authentication.service.ts`, `src/api-credentials/api-key-auth.guard.ts`). There is no unified dispatcher, controller, or public route using these guards.
- [ ] **API-key lifecycle is not exposed or fully wired.** Lifecycle service classes exist, but there are no management controllers. `ApiCredentialsModule` does not register/export `ApiKeyGenerationService` or `ApiCredentialLifecycleService`, and `AppModule` does not import `ApiCredentialsModule` (`src/api-credentials/api-credentials.module.ts`, `src/api-credentials/api-credential-lifecycle.service.ts`, `src/app.module.ts`). Treat key creation/list/revocation as implemented data/service primitives only, not an operable API.
- [ ] **Scope authorization is not attached to routes.** The decorator, evaluator, guard, and module exist, but `AuthorizationModule` is not imported by the root module and there are no controllers to protect (`src/authorization/authorization.module.ts`, `src/app.module.ts`).
- [ ] **Security-audit storage is not connected to security events.** The schema, repository, service, and module exist, but `SecurityAuditModule` is not imported by `AppModule`, and authentication/key lifecycle flows do not call the recorder (`src/security-audit/security-audit.module.ts`, `src/app.module.ts`). No end-to-end audit event is currently emitted.
- [ ] **MCP compatibility is boundary-only.** An external MCP can eventually call Auth through the same normalized Principal and gateway seams documented in `docs/integration-contracts.md`; no MCP server or final MCP OAuth flow exists in this repository.

## Deferred and human-gated decisions

- [ ] **Human role-to-scope matrix -- HUMAN_GATE.** Human Principals intentionally receive no scopes until exact permissions for `administrador`, `reservante`, and `viajero` are approved (`.loop/ARCHITECTURE_DECISIONS.md`, D-018/Q-001; `src/identity/human-principal-resolver.service.ts`).
- [ ] **Final MCP/ChatGPT OAuth design -- HUMAN_GATE.** Issuer, client registration, redirects, and token flow remain undecided (`.loop/ARCHITECTURE_DECISIONS.md`, Q-002).
- [ ] **Future signed Auth-to-Core assertion -- HUMAN_GATE.** Algorithm, keys, TTL, issuer/audience, and JWKS are not defined; V1 remains Noop (`.loop/ARCHITECTURE_DECISIONS.md`, D-004/Q-003).
- [ ] **Shared serverless rate limiting and trusted-proxy policy -- deferred/HUMAN_GATE.** Vercel instances cannot rely on process memory. No shared backend or trusted-proxy policy has been selected, so rate limiting is not implemented (`.loop/ARCHITECTURE_DECISIONS.md`, D-020). Credential-safe logging alone satisfied AUTH-015 for backlog dependency purposes; that bookkeeping decision is not evidence that rate limiting exists.
- [ ] **Supabase serverless connection pooler -- human verification required.** Confirm the pooler endpoint and connection limits before deployment; the current Prisma service creates its adapter from `DATABASE_URL` and does not establish that production pooling is correct (`src/database/prisma.service.ts`; `.loop/ARCHITECTURE_DECISIONS.md`, D-020).
- [ ] **Real migration review/application -- HUMAN_GATE.** Back up the database, inspect generated SQL, and apply only through a human-approved path. Never use autonomous reset, push, or deploy against Supabase (`.loop/PRISMA_SAFETY.md`).
- [ ] **Production secrets and configuration -- human-owned.** Provision real `DATABASE_URL`, `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `CORE_BASE_URL`, and timeout/runtime values through the deployment secret store; do not commit or log them (`src/config/environment.validation.ts`, `.env.example`).
- [ ] **Deployment -- absent.** No production deployment is performed or validated by this repository handoff.
- [ ] **Automated tests -- absent.** `package.json` has no test script, and this task does not introduce a test suite. Build and Prisma schema validation are the available deterministic checks.

## Explicitly absent and out of scope

- [ ] **Noktos Core is not implemented here.** Only the outbound Auth client seam exists.
- [ ] **Noktos MCP is not implemented here.** MCP remains a separate external service and must call Auth, never Core or the database directly.
- [ ] **Public business endpoints are not implemented.** The repository contains no controllers and defines no booking, traveler, hotel, reservation, or other domain route.
- [ ] **Runtime Swagger/OpenAPI wiring is not implemented.** `src/main.ts` only creates and listens with the Nest application.
- [ ] **Business/domain authorization rules are not implemented in Auth.** Concrete resource ownership and domain decisions belong in future Noktos Core; Auth currently provides only identity and general-scope primitives.
- [ ] **Rate limiting is not implemented.** Do not interpret request logging or any backlog dependency status as rate-limit enforcement.

## Pre-deployment human checklist

- [ ] Create and verify a recoverable Supabase backup/snapshot.
- [ ] Generate and manually review migration SQL before application; do not run `prisma migrate reset`, `prisma db push`, or `prisma migrate deploy` autonomously against a real database.
- [ ] Confirm reviewed SQL does not create, alter, drop, truncate, or otherwise mutate `public.user_info`.
- [ ] Confirm all repository-owned database changes affect only intended objects in the `noktos_auth` schema.
- [ ] Provision production secrets/configuration in the deployment platform and verify logs, error telemetry, and build output contain no JWTs, raw API keys, database credentials, or secret-bearing authorization headers.
- [ ] Verify the Supabase serverless connection-pooler endpoint, connection budget, Prisma adapter behavior, and Vercel concurrency characteristics under expected load.
- [ ] Select and approve a shared serverless rate-limit backend, define limits and failure behavior, and approve a trusted-proxy/client-IP policy; implement and validate them before production traffic.
- [ ] Ensure future Noktos Core is private at the network layer and reachable only from Noktos Auth; verify Web, Partner, and MCP consumers cannot bypass Auth.
- [ ] Complete the human-gated role/scope, MCP OAuth, and future Auth-to-Core assertion decisions before relying on the affected capabilities.
- [ ] Wire and review the required controllers/modules/guards, ingress request-ID generation, API-key administration, scope enforcement, and security-audit event emission before exposing public routes.
- [ ] Perform manual negative and positive security/integration validation for Supabase tokens, deterministic API-key dispatch, revoked/expired keys, scope denial, error sanitization, request-ID continuity, audit persistence, and log redaction.
- [ ] Add and run an appropriately scoped automated test strategy; the current repository has no automated tests.
- [ ] Run `npm run build --if-present` and `npx prisma validate` in the reviewed release environment without connecting to or mutating a production database.
